# Decisions

- Keep each reusable skill independent under `skills/<skill-name>/` with `SKILL.md` as the entry point.
- Keep `canon-skill` subject-agnostic: Canon Skill owns generic canon-respecting runtime semantics, Subject Packs own subject identity facts/references/calibration/validators/hooks/delivery policy, and generation backends own transport. Continuity may supplement but never replace canonical authority; generated images never become identity authority by recency; session-local runtime state never writes back to Subject Canon without an explicit subject-owned process.
- Keep the Canon runtime resolution order stable: resolve Subject Pack, then route, image operational roles, external-reference scopes, and minimum canonical evidence before freezing a Generation Packet. Image roles use `PROTECTED_CANONICAL > EDIT_TARGET > PREVIEW_SHOT_REFERENCE > ACCEPTED_CONTINUITY > EXPLICIT_EXTERNAL_ROLE > ORIGINAL_PROMPT_REFERENCE`; external and continuity evidence cannot satisfy missing canonical identity or structure coverage.
- Keep Canon result handling deterministic and severity-bounded: unresolved required dependencies are `BLOCKED`; only wrong identity, major structural/anatomy/geometry drift, or external identity contamination are `HARD_RESET`; operation misses are `RETRY_REQUIRED`; bounded local defects after Canon and shot compliance are `REFINE_ELIGIBLE`; only fully validated candidates are `ACCEPT`. A packet revision gets at most one automatic fresh retry after its first `HARD_RESET`, and failed/refine-only outputs never enter continuity.
- Keep `brand-design-system` identity-centric: establish brand foundation only when visual decisions depend on unresolved strategy; preserve explicit approval/master/QA gates; treat naming or visual clearance as a separately evidenced status rather than an inferred legal conclusion; keep tokens/manifests derivative of approved artwork; and do not expand the skill into standalone product UI component-library/design-system work.
- Keep formal public documentation synchronized between English and Chinese.
- Do not commit credentials, user data, generated caches, virtual environments, or local installation links.
- Use Agnir `repository-filesystem/0.1` with project-owned continuity memory under `.agnir/` and repository `main` as the authoritative ref.
- Retire the legacy `.chatgpt/` continuity files so Agnir is the single repository-managed durable Project truth.
- Host the public skill gallery on Cloudflare Pages, use `https://skills-hub.lapplax.com/` as the canonical public URL, retain the provider-assigned `pages.dev` address as the underlying Pages endpoint, and deploy only revisions that have passed repository validation and production acceptance; the previous `skills-hub` Cloudflare Worker remains retired.
- Keep the former `https://skills-hub.hkooii.com/` hostname as a legacy compatibility surface when it remains attached, but mark it `noindex`; canonical metadata, sitemap, documentation, and production acceptance target `skills-hub.lapplax.com`.
- Let the production workflow idempotently associate the canonical Pages custom domain through the Cloudflare Pages API and require the domain to reach `active` status before canonical-domain acceptance succeeds.
- Keep DNS mutation outside the continuing Pages deployment credential. The canonical CNAME `skills-hub.lapplax.com` -> `skills-hub-ea7.pages.dev` was provisioned as an external trust-boundary action; the production token remains scoped to Pages Edit rather than being broadened to DNS Write.
- Keep `ZEROLOCAL.yaml` aligned with the active Cloudflare Pages runtime, canonical URL, Pages permission boundary, and external DNS trust boundary; do not preserve Worker-specific runtime or token guidance after Worker retirement.
- Generate public catalog metadata and per-skill detail pages from each skill's `SKILL.md` and `agents/openai.yaml`; do not hand-maintain duplicate English skill descriptions, invocation prompts, or source provenance in site code.
- Keep full-site bilingual localization layered over canonical skill sources. Static UI copy remains dual-language in site assets; structured Simplified Chinese display names, short summaries, full scope descriptions, invocation examples, and complete website contract mirrors live in `locales/zh-CN.json`. English `SKILL.md` remains the canonical Agent instruction source used by ChatGPT and Codex; the Chinese `bodyMarkdown` is a website display mirror whose section structure, fenced code, and repository-relative references are validated against that canonical source. Formal `README.zh.md` summary and invocation copy must remain aligned with the structured localization source rather than being parsed as build data.
- Keep the public gallery dependency-free HTML/CSS/JavaScript. Support light and dark appearance across the catalog, generated skill pages, and 404 surface; default to the operating-system preference when no explicit choice exists, persist an explicit user choice locally, and keep the theme control language-aware and keyboard accessible.
- Treat generated HTML and root runtime JavaScript/CSS as one compatibility unit. Build deterministically computes a content hash over emitted runtime assets, appends that version to every runtime asset URL, and requires browser revalidation through Cloudflare Pages headers. Do not ship DOM/runtime contract changes behind stable unversioned asset URLs.
- Use maintained parsers for build-time YAML and Markdown semantics instead of repository-specific scalar/Markdown parsers; keep Markdown raw HTML disabled when rendering both English and localized skill contracts.
- Keep the gallery build deterministic apart from revision-bearing health metadata; do not add wall-clock timestamps to catalog data when no consumer requires them.
- Keep validation, installer exercises, production catalog acceptance, localization coverage, runtime-asset version checks, and browser smoke tests data-driven over the complete skill set; adding a skill must not require editing CI or deployment allowlists.
- Use a committed npm lockfile and `npm ci` in validation/deployment so parser and browser-test tooling resolve reproducibly. Keep deployment-only Wrangler outside the project dependency graph and pin its version in the deployment action.
- Reference reusable GitHub Actions by immutable commit SHA and use Dependabot to surface controlled updates rather than following moving major-version tags implicitly.
- Verify Cloudflare Pages delivery behavior externally after deployment, including security headers and the indexing boundary between provider `pages.dev` surfaces, legacy custom hosts, and the canonical custom domain.
