# Current State

- Project: `mattamior/skills-hub`, a repository for developing and maintaining reusable Agent Skills for ChatGPT and Codex.
- Skills live under `skills/<skill-name>/` and use `SKILL.md` as their entry point.
- The currently documented reusable skills are `brand-design-system` and `pet-avatar-generation`.
- The public gallery is deployed with Cloudflare Pages. The target canonical hostname is `https://skills-hub.lapplax.com/`, the provider-assigned `https://skills-hub-ea7.pages.dev/` address remains the underlying Pages URL, and the superseded `skills-hub` Cloudflare Worker remains retired. The former `https://skills-hub.hkooii.com/` hostname is treated as a legacy compatibility surface and excluded from indexing when it remains attached.
- The light/dark theme and new-domain site build were validated, merged, and deployed successfully at revision `9a9cf9f1981f0ab809212541c5ef3ec0a8c0a021`. Cloudflare accepted the `skills-hub.lapplax.com` Pages custom-domain association, but the hostname remains pending because its DNS CNAME has not been provisioned.
- A follow-up experiment at revision `3181f444ee94e35604e32c7ee2b66d3b9167709d` verified that the existing production Cloudflare token has Pages access but no DNS-zone access: the DNS records API for zone `4b6df08d4bb64fb0925d43d6bf492869` returned HTTP 403 with Cloudflare code `10000` (`Authentication error`).
- To preserve least privilege, continuing Pages deployment remains scoped to Pages Edit rather than permanently expanding the production token to DNS Write. The canonical-domain DNS record is a one-time external trust boundary: create CNAME `skills-hub.lapplax.com` pointing to `skills-hub-ea7.pages.dev`, then rerun production deployment so the Pages custom domain can become `active` and pass canonical acceptance.
- The public gallery is a repository-generated fully bilingual skill catalog: each skill gets a dedicated `/skills/<skill-name>/` detail page generated from `SKILL.md`, `agents/openai.yaml`, and structured Simplified Chinese localization in `locales/zh-CN.json`.
- Full-site Chinese mode covers homepage shell copy, catalog loading/search/result states, localized Skill display names, full scope descriptions, invocation examples, generated detail-page chrome, copy states, document titles, 404 metadata/content, and complete rendered Skill operating contracts. Technical identifiers and product/file names such as ChatGPT, Codex, GitHub, SKILL.md, slugs, commands, and filenames remain untranslated where translation would reduce precision.
- English `SKILL.md` remains the canonical Agent instruction source. Each Chinese `bodyMarkdown` entry is a website display mirror; localization validation requires the same level-two section count, non-code content-block count, fenced-code structure, repository-relative references, and any canonical explicit invocation that is present in the English contract.
- Formal Chinese documentation is validated against the structured localization source but is not parsed as build data. README alignment covers the canonical Chinese skill summary and invocation example.
- The public gallery visual shell remains dependency-free HTML/CSS/JavaScript and emphasizes fast skill discovery: a dense value-focused hero, repository/validation trust cues, policy and product metadata on skill cards, keyboard-first search with live result counts, strong responsive behavior, and visible focus/reduced-motion accessibility support.
- The catalog, generated skill pages, and branded 404 support persistent light/dark appearance. With no explicit preference the site follows the operating-system color scheme; an explicit toggle stores `light` or `dark` in local storage and keeps the control label synchronized with the active English or Chinese interface language.
- Gallery build-time YAML and Markdown semantics use maintained `yaml` and `markdown-it` packages with raw Markdown HTML disabled. `skills.json` is deterministic and omits wall-clock generation metadata; revision-bearing deployment identity remains in `health.json`.
- The gallery build emits canonical sitemap/robots metadata targeting `skills-hub.lapplax.com`, Cloudflare Pages security/indexing headers, Open Graph/Twitter metadata, and a bilingual noindex 404 page.
- Node dependencies are pinned through `package.json` plus a committed npm lockfile. Validation and deployment use `npm ci`; CI fixes Node at `22.23.2` and Python at `3.12.14`.
- GitHub Actions dependencies are referenced by immutable commit SHA, and Cloudflare deployment fixes Wrangler to `4.131.2`. Dependabot is configured to propose weekly npm and GitHub Actions dependency updates.
- Repository validation uses `./scripts/validate-skills.py`; GitHub Actions also checks Agent Skills compatibility, exercises the installer against the complete dynamically discovered skill set, builds and verifies the gallery, validates complete zh-CN contract coverage, and runs real Chromium smoke tests for catalog discovery/search shortcuts, language persistence, localized display names/contracts, theme persistence across site surfaces, skill-detail localization, clipboard copy, and branded 404 behavior.
- Production deployment is revision-bound: only an immutable validated commit is deployed to Cloudflare Pages. Acceptance compares the deployed catalog exactly with the locally built `skills.json`, requires matching revision and dynamic skill count in `health.json`, validates the sitemap, verifies security response headers, requires `pages.dev` surfaces to be `noindex`, and rejects `noindex` on the accepted canonical custom domain.
- Legacy `.chatgpt/` continuity files have been retired. `AGNIR.yaml` and the `.agnir/` locations it declares are the only repository-managed durable Project continuity.
- `ZEROLOCAL.yaml` describes the active Cloudflare Pages runtime, target canonical public URL, Pages-scoped deployment credential, and the one-time external DNS boundary rather than the retired Worker runtime.

- Several historical/topic branches remain in the remote repository; branch-ref deletion is not exposed by the connected GitHub capability, so branch cleanup remains an external repository-governance task.
