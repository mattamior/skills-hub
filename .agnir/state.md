# Current State

- Project: `mattamior/skills-hub`, a repository for developing and maintaining reusable Agent Skills for ChatGPT and Codex.
- Skills live under `skills/<skill-name>/` and use `SKILL.md` as their entry point.
- The currently documented reusable skills are `brand-design-system` and `pet-avatar-generation`.
- The public gallery is deployed with Cloudflare Pages and exposed canonically at `https://skills-hub.lapplax.com/`; the provider-assigned `https://skills-hub-ea7.pages.dev/` address remains the underlying Pages URL, and the superseded `skills-hub` Cloudflare Worker has been retired. The former `https://skills-hub.hkooii.com/` hostname is treated as a legacy compatibility surface and excluded from indexing when it remains attached.
- The production workflow idempotently associates `skills-hub.lapplax.com` with the Pages project through the Cloudflare Pages custom-domain API and requires the domain to become `active` before canonical-domain production acceptance succeeds.
- The public gallery is a repository-generated bilingual skill catalog: each skill gets a dedicated `/skills/<skill-name>/` detail page generated from `SKILL.md`, `agents/openai.yaml`, and structured Simplified Chinese catalog metadata in `locales/zh-CN.json`.
- The public gallery visual shell remains dependency-free HTML/CSS/JavaScript and emphasizes fast skill discovery: a dense value-focused hero, repository/validation trust cues, policy and product metadata on skill cards, keyboard-first search with live result counts, strong responsive behavior, and visible focus/reduced-motion accessibility support.
- The catalog, generated skill pages, and branded 404 now support persistent light/dark appearance. With no explicit preference the site follows the operating-system color scheme; an explicit toggle stores `light` or `dark` in local storage and keeps the control label synchronized with the active English or Chinese interface language.
- Formal Chinese documentation is validated against the structured localization source but is not parsed as build data. The rendered `SKILL.md` operating contract remains the canonical English source.
- Gallery build-time YAML and Markdown semantics use maintained `yaml` and `markdown-it` packages with raw Markdown HTML disabled. `skills.json` is deterministic and omits wall-clock generation metadata; revision-bearing deployment identity remains in `health.json`.
- The gallery build emits canonical sitemap/robots metadata for `skills-hub.lapplax.com`, Cloudflare Pages security/indexing headers, Open Graph/Twitter metadata, and a bilingual noindex 404 page.
- Node dependencies are pinned through `package.json` plus a committed npm lockfile. Validation and deployment use `npm ci`; CI fixes Node at `22.23.2` and Python at `3.12.14`.
- GitHub Actions dependencies are referenced by immutable commit SHA, and Cloudflare deployment fixes Wrangler to `4.131.2`. Dependabot is configured to propose weekly npm and GitHub Actions dependency updates.
- Repository validation uses `./scripts/validate-skills.py`; GitHub Actions also checks Agent Skills compatibility, exercises the installer against the complete dynamically discovered skill set, builds and verifies the gallery, and runs real Chromium smoke tests for catalog discovery/search shortcuts, language persistence, theme persistence across site surfaces, skill-detail localization, clipboard copy, and branded 404 behavior.
- Production deployment is revision-bound: only an immutable validated commit is deployed to Cloudflare Pages. Acceptance compares the deployed catalog exactly with the locally built `skills.json`, requires matching revision and dynamic skill count in `health.json`, validates the sitemap, verifies security response headers, requires `pages.dev` surfaces to be `noindex`, and rejects `noindex` on the canonical custom domain.
- Legacy `.chatgpt/` continuity files have been retired. `AGNIR.yaml` and the `.agnir/` locations it declares are the only repository-managed durable Project continuity.
- `ZEROLOCAL.yaml` describes the active Cloudflare Pages runtime, the canonical public URL, custom-domain provisioning boundary, and Pages-scoped deployment permission boundary rather than the retired Worker runtime.
- GitHub `main` currently has no branch protection or repository ruleset; adding a lightweight rule that requires validation and blocks destructive ref changes remains an external governance task because the connected GitHub capability does not expose ruleset mutation.
- Several historical/topic branches remain in the remote repository; branch-ref deletion is not exposed by the connected GitHub capability, so branch cleanup remains an external repository-governance task.
- Agnir Core `0.1` with discovery profile `repository-filesystem/0.1` is initialized, with colocated durable continuity under `.agnir/`.
- The Agnir operational package is upgraded compatibly to published `v0.1.1`, applied from immutable revision `e9712357ab590e5c1e5357b3cf3219d07d789aff`; Project identity and all declared memory locators/content were preserved.
