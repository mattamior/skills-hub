# Current State

- Project: `mattamior/skills-hub`, a repository for developing and maintaining reusable Agent Skills for ChatGPT and Codex.
- Skills live under `skills/<skill-name>/` and use `SKILL.md` as their entry point.
- The currently documented reusable skills are `brand-design-system`, `canon-skill`, and `pet-avatar-generation`.
- `canon-skill` has a Day 1 subject-agnostic contract scaffold: a thin routing `SKILL.md`, explicit architecture boundary, Subject Pack contract, evidence authority model, frozen Generation Packet contract, and Human/Pet/Virtual fixtures that share one generic top-level shape. Runtime resolvers, validators/recovery implementation, generation transport, and subject-project migration remain future work.
- `brand-design-system` remains identity-centric but now uses conditional brand-foundation scoping, explicit assignment/concept/master/QA exit gates, recorded clearance and lifecycle governance status, accessibility-aware brand-application QA, language/script validation, and optional stable DTCG-compatible token or asset-manifest delivery; standalone product UI component-library/design-system work remains out of scope.
- The public gallery is deployed with Cloudflare Pages and exposed canonically at `https://skills-hub.lapplax.com/`. The provider-assigned `https://skills-hub-ea7.pages.dev/` address remains the underlying Pages URL, and the superseded `skills-hub` Cloudflare Worker remains retired. The former `https://skills-hub.hkooii.com/` hostname is a legacy compatibility surface and is excluded from indexing when it remains attached.
- Revision `61dc33acbf75171018b4e8f680f04ef0dff33c43` passed full repository validation, deployed successfully to Cloudflare Pages, and passed exact-revision production acceptance on the canonical `skills-hub.lapplax.com` hostname. The Pages custom domain is active, so the canonical-domain cutover and its external CNAME prerequisite are complete.
- A migration experiment at revision `3181f444ee94e35604e32c7ee2b66d3b9167709d` verified that the production Cloudflare token has Pages access but no DNS-zone access: the DNS records API returned HTTP 403 with Cloudflare code `10000` (`Authentication error`). The canonical CNAME was therefore provisioned outside the continuing deployment credential, preserving the Pages Edit-only token boundary.
- The public gallery is a repository-generated fully bilingual skill catalog: each skill gets a dedicated `/skills/<skill-name>/` detail page generated from `SKILL.md`, `agents/openai.yaml`, and structured Simplified Chinese localization in `locales/zh-CN.json`.
- Full-site Chinese mode covers homepage shell copy, catalog loading/search/result states, localized Skill display names, full scope descriptions, invocation examples, generated detail-page chrome, copy states, document titles, 404 metadata/content, and complete rendered Skill operating contracts. Technical identifiers and product/file names such as ChatGPT, Codex, GitHub, SKILL.md, slugs, commands, and filenames remain untranslated where translation would reduce precision.
- English `SKILL.md` remains the canonical Agent instruction source. Each Chinese `bodyMarkdown` entry is a website display mirror; localization validation requires the same level-two section count, non-code content-block count, fenced-code structure, repository-relative references, and any canonical explicit invocation that is present in the English contract.
- Formal Chinese documentation is validated against the structured localization source but is not parsed as build data. README alignment covers the canonical Chinese skill summary and invocation example.
- The public gallery visual shell remains dependency-free HTML/CSS/JavaScript and emphasizes fast skill discovery: a dense value-focused hero, repository/validation trust cues, policy and product metadata on skill cards, keyboard-first search with live result counts, strong responsive behavior, and visible focus/reduced-motion accessibility support.
- Runtime JavaScript and CSS are emitted behind deterministic SHA-256 content-version query tokens, and Cloudflare Pages responses require browser revalidation with `Cache-Control: no-cache`. Generated HTML and runtime assets therefore advance as one compatibility unit instead of reusing an older `/detail.js` against newer `/skills/<slug>/` markup.
- The catalog, generated skill pages, and branded 404 support persistent light/dark appearance. With no explicit preference the site follows the operating-system color scheme; an explicit toggle stores `light` or `dark` in local storage and keeps the control label synchronized with the active English or Chinese interface language.
- Gallery build-time YAML and Markdown semantics use maintained `yaml` and `markdown-it` packages with raw Markdown HTML disabled. `skills.json` is deterministic and omits wall-clock generation metadata; revision-bearing deployment identity remains in `health.json`.
- The gallery build emits canonical sitemap/robots metadata targeting `skills-hub.lapplax.com`, Cloudflare Pages security/indexing headers, Open Graph/Twitter metadata, a deterministic runtime-asset version manifest, and a bilingual noindex 404 page.
- Node dependencies are pinned through `package.json` plus a committed npm lockfile. Validation and deployment use `npm ci`; CI fixes Node at `22.23.2` and Python at `3.12.14`.
- GitHub Actions dependencies are referenced by immutable commit SHA, and Cloudflare deployment fixes Wrangler to `4.131.2`. Dependabot is configured to propose weekly npm and GitHub Actions dependency updates.

Acceptance compares the deployed catalog exactly with the locally built `skills.json`, requires matching revision and dynamic skill count in `health.json`, validates the sitemap, verifies security response headers, requires `pages.dev` surfaces to be `noindex`, and rejects `noindex` on the canonical custom domain.
